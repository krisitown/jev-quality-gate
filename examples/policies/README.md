# Exploratory responsibility policy pack

This folder contains three separate policies for the bounded questions provided by this exploratory pack: shared-rule duplication, responsibility-boundary leakage, and responsibility entanglement. Their exact common convention is [`conventions.md`](conventions.md). The policies are schema-valid exploratory templates, not project-specific architecture rules or calibrated detectors.

To use them, make a trusted control bundle containing the convention document, bind it as `conventions` in the root JSON config, and set the document's SHA-256 to the hash of the exact copied bytes. Keep the config and policies in a trusted checkout separate from the candidate branch. The convention's content is intentionally generic; a repository's code, tests, public interfaces, and other stable contracts must supply the evidence for what its components and rules mean. An explicit architecture document is useful evidence but is not required by these policies.

All three policies use `jev.policy/0.2`, `introduced_or_worsened`, null confidence thresholds, and `report` for every outcome. Use `mode: calibration`; do not describe these settings as a production gate or as calibrated. The `GET_CALLERS` and `GET_CALLEES` request types can produce evidence only when the optional pinned Ripwire provider is configured. Its graph evidence is heuristic and partial. The baseline `git-exact` provider supplies changed chunks, exact files, trusted documents, and authored literal searches.

Evidence discovery has specific limits. Exact file requests are constructed for changed in-scope paths (a deleted path can be read from the base) and for policy-scoped files returned by a literal search. Search terms are authored in each YAML file; the candidate menu remains capped and may omit requests. An absent, empty, or partial result does not establish that a rule, dependency, or responsibility does not exist. Calls, callees, and symbol candidates are limited to changed symbols exposed by Ripwire, with incomplete heuristic coverage. During reconciliation, prior outcomes are summaries, not source evidence; changed paths are included to help select related chunks. If the available source/contracts do not establish the relevant equivalence, owner, boundary, or coupling, the policy must remain uncertain.

The scope globs select common source-code file extensions across repository layouts, including root-level files. Vendor, `node_modules`, and explicitly generated directories are excluded because those copies are not treated as independently maintained production rules here. Tests may clarify meaning or act as oracles, but are not independent production rules by themselves. The globs do not cover every language or generated/source format; a change outside the declared scope is not evaluated by that policy. Scope selection is part of the policy treatment and must be frozen before any evaluation.

Validate the included trusted bundle without an API call: `jev-ci validate --config examples/policies/config.json`. Its loop count, serialized input size and retrieval size are controlled by the root config. Per-policy `max_rounds`, `max_input_tokens` and `request_selection_min` are legacy metadata under v0.3; see [the loop contract](../../docs/design/evaluation-protocol.md).
